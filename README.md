# BangumiTagger

A MoonBit command-line tool for organizing local anime using [Bangumi](https://bangumi.github.io/api/) metadata and [Jellyfin naming conventions](https://jellyfin.org/docs/general/server/media/shows/). Preview a release before moving it. It does not copy or re-encode video, overwrite existing files, or control the Jellyfin service.

## Requirements

- Windows with local NTFS directories. Both library roots must be on the same volume.
- [MoonBit toolchain](https://www.moonbitlang.com/download) on PATH (tested with compiler v0.10.20+65efd5b93) and Node.js 22 or newer. No npm or Python dependencies.
- Network access to Bangumi. Add `--proxy http://127.0.0.1:7890` to `search` and `plan` if using a local HTTP proxy. Omit the option to connect directly. Public metadata usually does not require a token; if needed, set `BGM_TOKEN` in the current process environment. The tool does not save it.

The current version is CLI-only. Run `.\Start-BangumiTagger.cmd --help` from PowerShell or use `node launcher.cjs --help`. Do not pass a Python-era run record to the MoonBit CLI: the plan formats differ.

## Quick start

Run from the repository directory. The paths and subject below are examples.

~~~powershell
$shows = 'D:\Media\Shows'
$movies = 'D:\Media\Movies'
$source = 'D:\Media\Shows\Unsorted Release'

.\Start-BangumiTagger.cmd scan --shows-root $shows --movies-root $movies
.\Start-BangumiTagger.cmd search --query 'Dungeon Meshi'
.\Start-BangumiTagger.cmd plan --shows-root $shows --movies-root $movies --source $source --subject 395378
~~~

Review the saved `data/runs/<run-id>/plan.json`, especially `moves`, `outputs` and `review`. Preview can stage metadata in the state directory but never writes into either media library. To apply, replace `<run-id>` with the ID printed by `plan`:

~~~powershell
$run = '<run-id>'
.\Start-BangumiTagger.cmd apply --run $run --yes
.\Start-BangumiTagger.cmd verify --run $run
~~~

Refresh the corresponding library in Jellyfin yourself after verification.

## Matching and file handling

- **One release folder per plan.** Select a folder below one of the library roots. Videos must be directly inside it. A movie must have exactly one video in the folder; select its Bangumi subject with `--kind movie`. Existing movie folders containing a video are left alone.
- **Shows.** The planner matches explicit filenames such as `Title S01E02.mkv`, `Title S01E01-E02.mkv`, `Title [02].mkv` or `Title - 02.mkv` to Bangumi chapters. To combine a sequel, add `--root-subject` (the original series ID) and `--season 2`. `--episode-offset` subtracts a number from the filename's episode number; `--numbering ep` or `--numbering sort` selects which Bangumi field to use. The default `auto` refuses conflicting entries.
- **Companions.** Same-directory external subtitles and audio tracks are paired by exact video stem with optional suffixes, such as `.en.ass`. They keep their bytes and suffixes. No timing correction or remuxing is performed.
- **Metadata.** The tool stages show, season, episode and movie NFOs, plus real Bangumi posters when available. `--no-poster` skips image requests. Titles and descriptions retain Bangumi's language. The CLI does not delete or replace pre-existing NFOs or posters.
- **Unmatched files.** Special/extra filenames, nested folders, ambiguous episodes, unpaired subtitles and resources stay at the source. The scanner skips ignored folders, recognized extras folders and videos already covered by local NFOs. Empty files or videos modified in the last 120 seconds are not processed.
- **In-place transfer.** Moves use a same-volume hard link followed by unlinking the original path. This does not duplicate file data or overwrite a destination. An interruption between those steps can leave both names pointing to the same file, which `resume` can finish using the saved identity and journal.

## Recovery

Use `--data <directory>` on all run commands if you use a custom state directory. Keep that directory separate from both media libraries and don't publish it; it contains local file paths and staged metadata.

- `resume --run <id> --yes` continues an interrupted apply.
- `verify --run <id>` checks file identities and generated metadata digests.
- `rollback --run <id> --yes` restores the original paths and removes unmodified metadata generated by the run. It leaves destination directories in place and refuses to remove changed files.
- `unlock --data <directory> --yes` clears a lock only if its recorded process is no longer running.

Run only one operation against the same library at a time. Avoid changing source or destination files while a plan is executing.

## Development

Matching, metadata generation, plan validation and recovery are implemented in MoonBit. The JS backend uses a small Node host for filesystem and HTTPS calls. See the [MoonBit FFI documentation](https://docs.moonbitlang.com/en/stable/language/ffi.html).

~~~powershell
moon check --target js -d
moon test --target js
moon build --target js
node --test tests/integration.test.cjs
~~~

The integration tests use temporary directories and simulated Bangumi responses. They do not touch a real media library.
